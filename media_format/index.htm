The Archivist's Perspective on Digital Media

To an ordinary user, digital media appear as files that are supposed to display some kind of audio-visual content. They often open with no problem using your system's default app assigned to whatever media type that may be detectable. The question of what digital media is, or how it works is hidden frm the ordinary user and is irrelevant for ordinary purposes, as long as the display of the content looks right. Of course, this does not always work for various reasons. For a digital archivist the question of what a digital media file is, and how to make sure that they behave reliably demands a deeper-than-normal understanding of digital media.

The digital repository like Omeka does many things. A critical function is to serve as a container for master media files that are guaranteed to function reliably with unknown software in the future. What could possibly go wrong?

Media File Structure and Technical Lineage

Assuring that media files behave reliably in today's repository, and in repositories in the future, is covered in depth

  • Library of Congress Recommended Formats Statement
  • Federal Agencies Digital Guidlines Initiative, (FAGDI): Technical Guidelines for DigitizingCultural Heritage Materials( 2023) See the tables beginning on Page 27,
  • U.S. National Archives and Records Administration (NARA) Technical Guidelines for Digitizing Archival Materials for Electronic Access: Creation of Production Master Files – Raster Images Accessed from https://www.archives.gov/files/preservation/technical/ (See Page 60.

Whether a media file represents a scan, or an image from a cell-phone camera or a PDF that was saved from a digital document, the media file has three parts:

  1. The Bitstream: which is the graphical content: i.e. pixels, or formatted text or both.
  2. Technical Metadata that describes the device and the settings in play when the file was captured.
  3. A Preview thumbnail. Sometimes the tumbnail may be embedded in the file, or rendered on the fly by whatever system or tool you are using. Sometimes these previews interpret parameters the technical metadata like orientation/rotation, or color correction. Sometimes they don't. It depends on the tool and the settings.

A principle common to all digital archiving standards is that whenever possible, the original bitstream and technical metadata should be preserved with a minimum of extra manipulation.

TIF Format Profiles

The following properties can be evaluated for any image using your computer's file explorer. In Windows, right-click the image and choose properties.

TIFF Format

The TIFF format for digital images is a very flexible container for a variety of image encodings some of which are considered solid for archival use and many others, that are less portable. While TIFF is recommended, it is necessary to look at specific properties of the TIFF file to assure that the image will be most likely to be preserved and transferrable for the long-term.

File Names:

Even though WIndows and Apple operating systems may be more flexible in terms of file and folder names, our folder and file names should be compatible with the more universal conventions used by Linux OS amd web applications.

  • Use only alphabetical and numerical characters plus "-", and "_".
  • No spaces or tabs in filenames!
  • Tif files should end with a simple ".tif" suffix.

Single-Page Media

Although it may be possible to save Tif files with multiple pages (or frames), these files cannot be loaded into Omeka and are also problematic in other archival management applications. Therefore all images should contain a single page or frame.

Color Representation / Bit Depth:

  • 8 bits per channel.
  • Gray Scale: One Channel -- 8 bits.
  • Color: 3 Channel RGB -- 24 bits.
  • No transparency should be applied. Remove transparency you should Flatten the image and check to make sure that the result has a bit-depth of 24. (8-bits per channel.)
  • TIF images should use LZW compression

TIF Color Profiles:

Images exported from graphics and design applications often use color mapped images that apply Color Profiles other than simple RGB or sRGB. These should be avoided.

According to the NARA Guidelines (p38):

An ideal workflow would be to scan originals with a calibrated and characterized device, assign the profile of that device to the image file, and convert the file to the chosen workspace (Adobe RGB 1998 for color or Gray Gamma 2.2 for grayscale).

TIF Compression:

  • LZW Compression

Various scanners and file-save operations will default to other sorts of compression that will cause problems. Therefore it is important to choose tools and export functions that use No compression or LZW and make sure to check frequently that your images are safe.

Image Pixel Dimensions and DPI

The vast majority of physical holdings in the Architectural survey are letter-sized pages. The original scanning requirements were to make 24-bit RGB images at 200dpi. On average the pixel dimention of these images is about Pixel Dimension os the count of pixels for the height and width of the rectangular image. In most cases, our digital documents are less than 30" x 40' Inches scanned at 300 dpi. These images have approximately 2500 x 3500 pixels and compressed with the LZW process, are around 4 megabytes each. Occaisionally there is a 30x40 drawing scanned at 300dpi might be contributed. SUch an image would be 6000x8000 pixels. A file such as this, uncompressed would be approximately This would be a maximum pixel dimension of 6000 x 8000 pixels, and may weigh in at around 100mb. This would be the limit for pixel dimension and file size.

TIF Rendering and Migration Rules

Embedded Technical Metadata in TIF files, whether it be native TIF tags, XMP or EXIF, will be preserved disregarded in rendereing and other transformations. This means that any rotation or color profiles assigned to these files should be baked-in to the RGB bit-stream.

Quick Links for Scanning and Saving Archival PDFs

PDF format documents are easy to handle today. A hundred years from now, we probably should expect problems. Features that make PDFs compact today, such as relying on external font libraries or clever media or compression formats are all likely to cause problems in the future. Luckily for us, archivists have come up with a common denominator for packaging documents as Archival PDF documents. We can be reasonably sure that archival tools of the future will be able to read these and if necessary import these into the archival systems of the future, or to migrate these to digital document formats of the future, if necessary.

Tools For Handling and Checking Image Files

When scanning documents and manipulating the results, use a tool that allows you to

  • Inspect and set the color profile
  • Flatten the image to remove transparency
  • Set the compression format

To determine whether an image is formatted correctly, you can inspect its properties by right-clicking it in Windows, choose Properties, and then inspect the Details tab.

If you ware experimenting with a new workflow and want to test your images for compatibility with the Omeka importer, try importing the the image as media for an item in the Stage instance.
